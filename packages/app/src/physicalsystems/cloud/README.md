# Shared cloud conversation

`CloudConversation` reuses the canonical OpenCode V2 timeline projection, row renderer and `ComposerEditor`. It consumes V2 session records directly without the former message/part normalization. The native app mounts it directly with `conversation.css`. The website uses the source export's isolated same-origin frame, which imports the canonical style layers and exposes `window.physicalSystemsCloudConversation.mount(document.getElementById("app"), options)`.

Options are `accountKey`, `workcellId`, `conversationId`, `transport`, optional `theme`, optional authenticated `workcell` context and optional `allowAi` (default true). Workcell-only native grants set `allowAi:false`, so the component never requests runtime or prompt endpoints. `accountKey` is a non-secret stable user identifier, never a token or grant/session identifier: same-account reauthorization must recover its queued sends. The host must replace the transport and dispose/remount the view whenever authentication changes, including same-user token changes. `mount` returns `{dispose, update}`; identity or transport changes remount the entire conversation and cancel outstanding work. The host supplies no worker address, arbitrary route, filesystem path, provider/model setting or credentials to this UI.

The transport permits exactly:

- `GET /api/workcells/:workcellId/conversations/:conversationId` for authenticated conversation metadata, posting permissions and its latest 100 saved messages.
- `GET .../:conversationId/events?after=<sequence>&limit=100` replays all missed saved messages in sequence, including more than one page. Initial/latest history is not used to skip the forward cursor.
- `GET .../:conversationId/messages?before=<exclusive sequence>&limit=100` loads earlier messages. Its response never advances the live cursor.
- `POST .../:conversationId/messages` with `{requestId,content}` saves a member message, with 1–8,000 trimmed characters. Exact retries return the same durable message. No AI request or robot action is implied.
- `GET /api/workcells/:workcellId/conversations/:conversationId/runtime` returning `CloudConversationSnapshot` from `types.ts`. Canonical `SessionInfo` and `SessionMessageInfo[]` come from the worker's projected `/api/session/:id/message` endpoint, not raw durable history or compacted provider context. `runtime.status` explicitly distinguishes `ready` and `unavailable`; a new ready conversation may have `session:null` and no messages.
- `POST /api/workcells/:workcellId/conversations/:conversationId/prompts` with `{requestId,text}`; text is 1–32,000 characters. Successful admission returns `{requestId,admitted:true}` with the exact request ID. Server-side authorization, idempotency and all worker execution restrictions remain mandatory.

Saved-message polling runs every five seconds, with one-second paginated catch-up; AI polling is separate (five seconds idle, 1.5 seconds busy). Hidden documents pause polling; focus, visibility and reconnect refresh it. Read-only access hides the composer. Lost access clears the rendered history and in-memory draft and aborts requests; persistent drafts and queued sends remain isolated under the original account/workcell/conversation. They are not displayed or uploaded until that same account can access the conversation again.

Message and AI drafts are separate local-storage records. Each pending send has its own UUID-suffixed local-storage key (at most 20 per action/conversation), so concurrent tabs cannot overwrite another request or remove it when confirming their own receipt. Member SEND intents retry only after an authorized refresh, one at a time with 5–60-second backoff. Merely typed drafts never send automatically. AI requests always require explicit retry, including after restart; existing v1 session-storage AI receipts migrate to durable v2 records without dispatching. HTTP 408/429/5xx and authorization loss preserve uncertain sends; definitive other 4xx resolve them. Browser transports must preserve safe error status/code and suppress stale account responses. No credentials are persisted in these records, and no local shell, attachments, arbitrary tools or file previews are exposed.

The default **Message** action remains usable without an AI worker. Saved member/system messages show their authors and dates. Optional **Ask AI** sends only its own draft and renders canonical worker history in a separately labelled section. Saved messages are never relabelled as assistant replies or silently supplied as AI context. Local OpenCode projects/files/history are not uploaded by this component.

When authenticated workcell context is supplied, **Use task details** copies its saved name, task, objects and location into an empty editable draft. It explicitly labels those fields as supplied context, not live observations. It never sends automatically, overwrites an existing draft or changes an unresolved retry. The worker receives only the text the user chooses to send; displaying the context panel does not silently send task data to a model.
